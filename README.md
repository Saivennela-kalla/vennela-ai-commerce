# vennela

Vennela is a merchant-growth workspace for the AI-buyer era. It translates conversational buyer intent into a structured, explainable purchase proposal, surfaces the revenue opportunity to a merchant, and stops at a mandatory approval gate before any payment proposal is created.

The buildathon story is deliberately narrow: **make a merchant legible to AI buyers without making money movement invisible**.

## What is implemented

The runnable prototype includes a merchant growth overview for Aster & Row, a machine-readable product catalog, an LLM-backed AI-buyer proposal flow, a merchant approval gate, a bounded Razorpay test-mode payment proposal adapter, an append-only-style decision trail, and a graceful failed-payment recovery path.

The policy used by the demo is explicit. The maximum proposal is ₹9,000, the maximum upsell is ₹2,500, products below the inventory floor are excluded, and merchant approval is required. The frontend makes the policy visible before the merchant can create a payment proposal. The app never silently charges a buyer.

## Demo flow

1. Open the workspace and select **AI buyer lab**.
2. Submit a request such as “I need a warm, calm desk setup for my new apartment. Nothing too loud.”
3. Review the structured proposal, rationale, selected products, upsell, total, and guardrails.
4. Tick the merchant approval checkbox. The primary action remains disabled until approval is explicit.
5. Create the test-mode payment proposal. The result shows the order reference, test environment, and “Not charged” state.
6. Use **Simulate safe timeout** to see the failure path. The app preserves the approval context and offers a retry with the same bounded proposal.
7. Open **Decision trail** to inspect the event sequence from intent interpretation to policy checks, approval requirement, payment outcome, and recovery.

## Architecture

The project uses a React and Tailwind frontend with an Express/tRPC server. The LLM call is server-side and requests a structured JSON response. If the model is unavailable, the prototype falls back to deterministic catalog matching, then re-applies the same policy bounds before returning the proposal. Razorpay credentials are optional for the demo; without credentials, the server uses a clearly labelled test-mode adapter that creates a sandbox order reference. If credentials are provided, the adapter accepts only a key beginning with `rzp_test_` and calls the Razorpay Orders API server-side.

No customer review, rating, or testimonial data is fabricated in this project.

## Run locally

```bash
pnpm install
pnpm dev
```

The app is designed to run in the managed project environment. For a real Razorpay test-mode order call, add server-side test credentials through the project secret manager rather than committing a `.env` file.

```text
RAZORPAY_KEY_ID=rzp_test_...
RAZORPAY_KEY_SECRET=...
```

Never use live keys with this prototype. The backend rejects a key that does not start with `rzp_test_`.

## Product principles

Vennela is opinionated about the payment boundary. Recommendations may be generated by an agent, but a money action is always explainable, policy-bounded, and merchant-gated. The system treats failure as a visible state to recover from rather than an invisible retry loop. Catalog data is structured so that an AI buyer can understand product identity, price, inventory, semantic tags, and allowed complement edges without guessing.
